**기간** 2025.06 ~ 2026.05 · **역할** 담당 개발자 · **스택** Spring Boot 2.7, 전자정부 표준프레임워크(eGovFrame), PostgreSQL, Thymeleaf, MQTT, Jenkins

> **기여도: 변경 라인 기준 89%, 커밋 기준 72%** — 기본 브랜치 병합 제외 커밋 135/186, 변경 130,901/145,572줄. 과제 담당자로 지정되어 개발·데모·배포 자동화를 맡음.

## 배경

출입 게이트 장비가 보내는 통과·알람 이벤트를 한 화면에서 보는 관제 대시보드입니다. 연구소 자체 과제로 진행됐고, 단계별 목표가 정해져 있었습니다.

| 단계 | 일정 | 목표 |
|---|---|---|
| 선행 Alpha | 2025.08.22 | 기본 개념 기능 (전체의 50%) |
| 선행 Beta | 2025.09.26 | 확정 기능 완료 (80%) |
| 선행 RC | 2025.10.31 | 변경 기능까지 완료 (100%) |

## 구현

- **여러 게이트 동시 모니터링**: 게이트 2대 이상을 한 화면에서 보고, 게이트·통신 연결 현황판을 따로 두었습니다.
- **통계 화면**: 일·월·연·전체 단위로 지점별·통로별 통과(IN/OUT)와 알람 현황을 표와 그래프(막대·원형 선택)로 보여 줍니다. 모든 동작에 타임스탬프를 남겨 시간 순으로 추적할 수 있습니다.
- **성능**: 시간대별 차트와 통계 페이지는 지연 로딩(Lazy Loading)으로 바꿔 첫 화면이 바로 뜨게 했습니다.
- **장비 연동**: MQTT 통신을 붙이고 시간 처리 로직을 정리했습니다.
- **기타**: 다국어 지원, 설정 파일(properties) 암호화, 설정 디렉터리 구조 정리.

2025년 12월에는 전시 데모부스에서 대시보드를 운영하며 매일 점검 기록을 남겼습니다.

## 배포 자동화 (2026)

서버에 손으로 올리던 배포를 Jenkins **원클릭 배포**로 바꿨습니다.

- DB 초기화(bootstrap), nginx 설정, 운영 환경 배포를 한 파이프라인으로 묶음
- 실제로 부딪힌 문제를 하나씩 해결
  - DB 초기화 시 비밀번호 입력 방식(stdin과 heredoc) 충돌
  - 인증서 파일 권한과 SELinux 때문에 nginx reload가 실패 → 원인별 대응과 폴백 추가
  - 배포 후 상태 확인(Health Check) 주소와 대기 시간 보강
- 정적 분석(SonarQube), 커버리지(JaCoCo), SBOM(CycloneDX)을 빌드에 연결
- v1.0.1, v1.0.2 태그 릴리스

## 문제와 해결

| 문제 | 원인 | 해결 |
|---|---|---|
| 통계 화면 첫 로딩이 느림 | 차트·통계 데이터를 한 번에 모두 불러옴 | 지연 로딩으로 전환 |
| DB 초기화 단계 실패 | 비밀번호를 stdin으로 넘기는 방식과 heredoc이 충돌 | 입력 방식 분리 |
| 배포 후 nginx reload 실패 | 인증서 파일 권한, SELinux 정책 | 원인별 대응 + 실패 시 폴백 |
| 배포 단계 스크립트 파싱 오류 | Jenkinsfile(Groovy) 안 셸 블록의 특수문자 해석 | 셸 블록 이스케이프 정리 |
| 배포 직후 상태 확인 실패 | 확인 주소와 기동 대기 시간이 실제와 안 맞음 | Health Check 주소·대기 시간 보강 |
| 설정 파일에 접속 정보가 평문 | properties에 값이 그대로 들어 있음 | properties 암호화 적용 |

## 배운 점

단계별 기능 비율이 정해진 일정이라, 화면을 먼저 다 만들기보다 핵심 흐름(이벤트 수신 → 저장 → 조회)을 먼저 끝까지 연결하고 통계·편의 기능을 붙이는 순서로 진행했습니다. 배포 자동화를 하면서 "내 PC에서는 되는" 설정이 서버의 권한·보안 정책에서 깨지는 경우를 많이 겪었고, 이 경험이 이후 인프라 업무로 넘어가는 계기가 됐습니다.
